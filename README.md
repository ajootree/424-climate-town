# 다섯 마을 수호대 — 햇살마을·온샘마을

초등 과학 「기후변화와 우리 생활」을 바탕으로 한 무광 동화풍 2D 횡스크롤 RPG입니다. 헤어 4가지·머리색 4가지 조합과 이름 짓기, 삽화 도입부, 두 마을의 학습 주제 10개와 순서대로 받는 부탁 16개, 포탈 전투와 수호석 2개 회복까지 플레이할 수 있습니다.

게임 실행: https://ajootree.github.io/424-climate-town/

소스 저장소: https://github.com/ajootree/424-climate-town

GitHub Pages 최초 설정: 저장소 Settings → Pages → Source를 Deploy from a branch, Branch를 main, 폴더를 / (root)로 선택하고 Save합니다. 이 설정 후 main에 새 커밋을 올리면 게임 페이지가 자동 갱신됩니다. 정적 파일이라 별도 빌드 명령은 필요하지 않습니다.

## 실행과 배포

정적 HTML·JavaScript·이미지로 구성되어 서버 코드, API 키, 로그인, 런타임 의존성 설치가 필요하지 않습니다. GitHub Pages는 main 브랜치의 저장소 루트(/)에서 배포하도록 설정하며, main에 새 변경을 올리면 같은 주소가 갱신됩니다. .nojekyll을 유지합니다.

Vercel과 Cloudflare Pages에도 같은 파일을 배포할 수 있습니다. 별도 빌드 없이 루트 폴더를 정적 출력으로 사용합니다. vercel.json을 포함했습니다.

## 조작

- 태블릿·스마트폰 가로: 원형 조이패드, 오른쪽 아래의 공격·대화 겸용 버튼, 점프·스킬·기력 충전 버튼. 이동과 공격 동시 터치를 지원합니다.
- 걷기는 서로 다른 여섯 자세를 실제 이동 거리에 맞춰 재생합니다. 고정 크기와 공통 발 기준선을 사용하고 머리는 각 자세의 U자 옷깃 안쪽을 기준으로 붙여 목이 옷깃 뒤에 겹치도록 합니다. 멈추거나 맵 끝에 막히면 제자리걸음을 하지 않습니다.
- 컴퓨터: 좌우 방향키 또는 A/D, Space 점프, Z 기본 행동(공격·대화·조사), X 스킬, E 대화·조사, Q 기력 충전, Esc 메뉴.
- 기력 문제를 읽는 동안 전투가 멈춥니다. 정답이면 20 회복, 오답이면 힌트를 보고 재도전합니다. 기본 공격은 10, 스킬은 25를 소모합니다.
- 보스는 근접 공격과 저주 씨앗 낙하 마법을 번갈아 사용합니다. 1.5초 동안 바닥에 위치를 예고한 뒤 씨앗이 떨어지며, 예고된 위치는 플레이어를 따라가지 않습니다. 체력 절반 이하에서는 두 곳을 노립니다. 메뉴·문제 창에서는 멈추고 퇴각·처치 시 남은 마법은 사라집니다. 보스 몸 가장자리까지 공격이 닿고 접촉·근접 피해 범위는 줄여, 조금 떨어져 공격할 수 있습니다.
- 머리 위 물음표는 수호석 보관을 결심하는 자기 퀘스트를 받을 때만 표시합니다. 다음 할 일은 오른쪽 위 부탁 칸의 물음표 버튼에서 혼잣말로 확인합니다. NPC의 새 부탁·처치 보고는 같은 종이 말풍선의 느낌표로 표시합니다. 수호석을 챙기기로 결심한 뒤 촌장님과 대화하면 가호를 받고 머리 위 말풍선은 웃는 얼굴로 바뀝니다. 햇살마을의 가호는 최대 기력100→120, 온샘마을의 가호는120→140이며 중복 지급하지 않습니다.
- 햇살마을 오른쪽 길의 편지 삽화를 보고 온샘마을에 들어갑니다. 머리·색·이름·경험치·배운 스킬·수호석·가호와 지난 마을의 학습/첫 평가 기록을 보존하고 새 퀘스트를 시작합니다. 수첩의 수호석 가방에서 두 마을의 수집 상태와 첫 확인 결과를 봅니다.
- 온샘마을 주민은 땋은 회색 머리 촌장님, 키 큰 배달원, 수염 난 쉼터 선생님, 단발머리 관측소 선생님입니다. 햇살마을과 얼굴·체형·나이·복장·실루엣이 다른 생성 이미지4종을 사용합니다. 스킬 버튼은 주변 아이콘의 잘린 조각이 없는 단독 원형 이미지입니다.
- 온샘마을은 얼어붙은 장터 조사, 야외 배달 계획, 외투·장갑·수도관 보온재, 생활·재산 피해와 오랜 기록, 서리 덩굴 전투와 대응의 다섯 부탁입니다. 전용 겨울 배경·NPC·몬스터·물품·수호석과 얼음 낙하 마법 그림을 사용합니다. 푸른들마을은 다음 편지 예고까지이며 아직 플레이 구간이 없습니다.
- NPC는 촌장님·배달원·쉼터 선생님·관측소 선생님으로 표시합니다.
- 긴 글을 줄이고 한 줄 목표, 짧은 대사, 상황 그림 선택지를 사용합니다. 대사는 초당 22글자로 나타나며, 한 번 누르면 전체 표시하고 다시 누르면 다음으로 넘어갑니다.
- 새 모험에서 삐친 짧은 머리·일자 단발·둥근 곱슬·가르마 묶음 중 하나와 갈색·검정·금색·남색 중 하나를 골라 16가지 모습을 조합합니다. 큰 미리보기에 즉시 반영되며 머리 모양과 색은 유지하며 표정은 평소·공격·피격·학습·보상 상황에 따라 자동으로 바뀝니다. 이름은 8글자까지 저장합니다. 이어하기는 외형·이름·진행을 유지하고 바로 모험으로 돌아갑니다. 새 캐릭터 만들기를 취소해도 기존 저장은 유지합니다.
- 배달원·쉼터 선생님·촌장님이 부탁을 주면 바로 옆에 전투 포탈이 열립니다. 포탈 입장 준비를 열면 잠깐 쉬어 체력을 회복합니다. 기력은 마을 화면의 책 버튼에서 문제로 채울 수 있고, 전투 중 마을로 돌아와 다시 준비할 수 있습니다. 마을에는 몬스터가 없습니다. 복합 부탁은 몬스터 처치 → NPC에게 처치 보고 → 별도의 물품 부탁 수락 → 물품 수집·학습 → 완료 보고 순서입니다. 배달원·쉼터 선생님·촌장님의 부탁 모두 이 흐름을 사용합니다. 물품 부탁을 받기 전에는 상자·쉼터 물품·수호석이 나타나지 않습니다. 배달은 새 부탁을 받은 뒤 계획을 정하고 상자 두 개를 각각 퀴즈와 함께 찾습니다. 안내는 남은 물품이 있으면 수집을, 전부 마쳤을 때만 완료 보고를 가리킵니다.
- 도입 삽화에는 작은 줌과 떠오르는 움직임을 사용합니다. 저주가 퍼졌다는 장면 뒤 0.65초 암전 페이드와 짧은 검은 화면, 황폐한 다섯 마을 삽화의 페이드 인을 보여줍니다. 재해 이름을 미리 나열하지 않고 주민·단서를 통해 알아가는 흐름입니다. 마을 배경은 서쪽·중앙·동쪽의 서로 다른 생성 원화를 한 번씩 연결한 5300×720 파노라마이며, 두 전투 지역은 각각 2200×720의 넓은 원화를 사용합니다. 좌우 반전·반복 타일을 사용하지 않습니다. 그림 연결부는 빈 가장자리만 겹치고, 실제 플레이 화면에서는 완성된 배경을 카메라와 1:1로 이동시킵니다.

가까운 NPC와 대화할 수 있거나 물품·포탈을 조사할 수 있으면 오른쪽 아래 공격 버튼이 해당 행동으로 바뀝니다. 화면 가운데의 대화 버튼은 없습니다. 메뉴는 오른쪽 위 X, 모험 계속 버튼, Esc로 닫습니다. 버튼은 실행할 일(배달 시간 정하기·기록 비교하기·창 닫기 등)을 표시합니다. 꾸미기·시작·포탈·메뉴의 반복 설명은 줄이고 목표와 필요한 조작만 남겼습니다. 캐릭터는 닫힌 옷깃 그림을 머리 앞에 겹쳐 목 접합부를 가리고, 이름을 초상화 카드 안의 별도 프레임에 넣었습니다.

첫 퀘스트는 날씨의 모습과 현상의 이름을 분리해 4개, 나머지는 3개씩 총 16개의 필수 학습 선택을 해결합니다. 배달 시간 계획, 쉼터 물품의 쓰임, 오랜 관측 기록 비교가 실제 진행 조건에 연결됩니다. 마지막에는 다른 상황의 확인 문제 5개를 풀고, 틀린 개념만 새 문항으로 다시 확인합니다. 첫 도전 점수와 재확인 완료를 따로 저장하며, 기력 충전 문제는 이 기록을 대신하지 않습니다. 수첩에서 개념과 결과를 다시 볼 수 있습니다. 학습 목표·자료 범위·평가 방식은 [LEARNING.md](LEARNING.md)를 참고하세요.

모든 배경·캐릭터·몬스터·물품·UI 프레임·터치 버튼은 생성 이미지입니다. Canvas는 이미지 배치와 애니메이션, 입력·충돌·글자·게이지를 처리합니다. CSS로 게임 오브젝트를 그리거나 이모지로 대체하지 않습니다.

폰트는 제목·버튼·캐릭터 이름에 넥슨 Lv.1 고딕 Bold, 대사·문제·나레이션·퀘스트 설명에 넥슨 Lv.2 고딕을 사용합니다. 실제 WOFF 파일을 assets/fonts에 포함하며 글꼴 로딩 후 게임을 그립니다. 폰트 저작권은 넥슨에 있으며 사용정책·원본 출처·파일 검증 정보는 assets/fonts/LICENSE.txt와 sources.json에 보존합니다.

진행은 현재 브라우저에 자동 저장됩니다. 다른 기기 또는 도메인으로 저장이 자동 이동하지 않습니다. 음성 읽어주기 없이 짧은 대사가 타자기처럼 표시됩니다. 대사나 버튼을 한 번 누르면 전체 표시, 다시 누르면 다음 대사로 넘어갑니다. 메뉴에서 효과음을 켜고 끌 수 있습니다. 배경과 월드 오브젝트는 같은 카메라 이동량을 사용하며, 획득한 물품은 이미지가 떠오르고 반짝이며 사라집니다. 관측판의 6일/12일은 실제 통계가 아닌 게임용 가상 자료로 표시합니다.

## 복합 부탁 추가

각 마을은 학습 주제 5개를 유지하되, 전투와 물품을 별도 부탁으로 표시해 순차 부탁은 8개입니다. `REQUESTS`의 NPC·적 종류·처치 수·수집 항목·표제·수락 버튼을 공통으로 사용합니다. `taskPhases`는 전투(0), 처치 보고 후 새 부탁 대기(1), 물품 부탁 수락(2)을 저장하며, 상태 모델과 화면 모두 수락 전 수집을 막습니다. 앞으로 추가하는 복합 부탁도 이 공통 흐름에 등록하고 같은 순서 검사를 적용합니다. 옛 저장의 이미 수집한 물품은 보존합니다.

## 개발 검사

npm ci 후 npm test, npm run check를 실행합니다. 게임을 실행하는 데 npm은 필요하지 않습니다. 검사는 상태·저장·캐릭터 설정 단위 16개와 실제 Canvas 엔진 통합 14개를 포함해 총 30개입니다. 키보드·조이패드·동시 터치·퀘스트 5개·포탈 전투·기력 충전·보스·엔딩, 대사·카메라·획득 연출, 준비·퇴각·재입장·기존 저장 이전, 머리 모양·색 16가지 조합의 실제 이미지 차이와 상황별 자동 표정 전환, 저주 뒤 암전과 황폐한 삽화 전환, 학습 선택과 물품 설치/보상 연결, 첫 평가 점수 보존과 오답 영역 재확인, 문항의 명칭 분리와 천 관련 선택지, 오른쪽 기본 행동 전환과 메뉴 X의 터치 닫기를 확인합니다. 옛 완료 저장의 수호석 이전, 생각→가호→마을 이동, 최대 기력 및 중복 보상 방지, 첫 평가 기록 보존과 한파 마을의 다섯 퀘스트·두 번째 수호석·두 번째 가호를 끝까지 확인합니다. 배경은 서로 먼 구간이 반복되지 않는지, 카메라 10픽셀 이동에 배경도 10픽셀 이동하는지 실제 픽셀로 비교합니다. 여섯 걷기 자세의 고정 크기와 목 위치, 맵 끝 정지, 마을별 주민 구분, 스킬 버튼 외부 조각 제거, 자기 퀘스트 물음표·NPC 느낌표·고정 도움말과 완료 웃음 말풍선도 확인합니다. 이어하기와 새 캐릭터 만들기 취소 뒤 외형 보존, 두 마을의 모든 복합 부탁에서 전투·보고·새 수락·수집의 순서와 중간 저장, 상자 한 개만 찾은 경우의 안내를 확인합니다. 걷기의 목 접합은 머리 모양·색·표정·자세 384개 조합으로 검사합니다. 화면 렌더링은 PC 1280×720, 태블릿 1024×768, 스마트폰 가로 932×430으로 확인합니다. 실제 모바일 기기의 입력·오디오·성능은 별도 확인이 필요합니다.

첫 마을은 15~20분을 목표로 설계했으며 실제 학생 플레이 시간은 아직 측정하지 않았습니다.

## 단독 HTML 내보내기

node scripts/export-offline.mjs standalone.html 명령으로 이미지까지 포함한 한 개의 HTML을 만듭니다. 원본 이미지와 게임 소스는 수정하지 않습니다. 로컬 HTML 실행 가능 여부는 기기 브라우저와 파일 앱 정책에 따라 다릅니다.
